같은 글을 세 번 다시 쓰지 않으려고 만들고 있는 작은 도구. 단일 진실 원본은 MDX 파일 하나, 봇이 플랫폼별로 톤을 바꿔서 올리고 반응을 다시 한 대시보드에 모은다.

## 무엇을 하는가

- 블로그에서 발행된 글을 webhook으로 받음.
- LLM에게 플랫폼별로 톤 변환 요청: X는 punchy thread, LinkedIn은 더 긴 narrative, Dev.to는 풀 본문.
- 각 플랫폼 API로 발행하고 응답 ID 저장.
- 플랫폼별 조회수/반응을 모은 작은 대시보드.

## 현재 상태

- ✓ LinkedIn + X 발행 + ID 역기록.
- ✓ Style transfer 프롬프트 + calibration set.
- ☐ Dev.to 연동.
- ☐ Engagement back-fill (7일간 하루 1회 폴링).

## 다시 한다면

Style transfer 프롬프트가 가장 어려웠다. 첫 버전이 너무 "LinkedIn 구루" 톤이라, *좋은* 글의 작은 eval set을 만들어서 거기에 맞춰 반복해야 했다.
